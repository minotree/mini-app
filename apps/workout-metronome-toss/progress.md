# 모두의 비트 토스 미니앱 진행표

## 현재 상태 (2026-11-04)

- 사용자 제공 토스 콘솔 화면에서 주요 기능 `운동 리듬 설정 / Rhythm Setup`, `인터벌 운동 / Interval Workout`을 각각 홈 화면 이동으로 입력했고, 영어 이름의 입력 오류가 사라진 것을 확인했다. 앱 검색 키워드 10개는 `메트로놈`, `운동`, `리듬`, `인터벌`, `걷기`, `자전거`, `운동박자`, `BPM`, `러닝`, `케이던스`로 입력된 화면을 확인했다. 이 기록은 콘솔 입력 화면 확인이며 검토 요청·승인·출시 완료를 뜻하지 않는다.
- 토스 콘솔 등록용 앱 로고 `assets/moduibeat-logo-600.png`를 600×600 PNG로 만들었다. 짙은 남색 바탕에 밝은 하늘색 메트로놈과 비트 파형을 직접 생성했으며, 동일 파일을 일반·다크 로고 입력란에 사용할 수 있다. 생성 기록: 2026-11-04, OpenAI 내장 `image_gen`(세부 모델명 미제공), 입력 자료 없음, 프롬프트는 “Square app icon for '모두의 비트', a workout metronome app. Flat vector-like single centered geometric pendulum and beat mark, pale cyan #b7f1ff on solid deep navy #10131b, generous margins, strong small-size silhouette. No text, gradients, shadows, border, watermark or mockup.” 외부 자료·기존 상표를 입력하지 않았고 눈에 띄는 제3자 로고는 없으나, 상표 유사성의 최종 검토는 등록 전에 필요하다.
- 사용자 제공 짧은 운동 화면에서 초기화 버튼과 하단 오디오 안내가 붙어 보이는 문제를 확인했다. 안내문 위 간격을 기본 1rem, 낮은 가로 화면에서 .75rem으로 지정하고 안내문이 줄어들지 않게 했다. 실제 토스 실기기에서 버튼·안내 간격은 새 빌드로 재확인해야 한다.
- 완료 화면이 남는 높이를 활용하도록 운동 종류·환경 카드와 인터벌 구성(일반 운동은 리듬 설정) 카드 2개를 추가했다. 운동 시간·상세 2개·칼로리 안내의 네 영역이 사용 가능한 높이에 맞춰 늘어나고, 다시 시작·설정 버튼은 화면 아래에 둔다. 작은 높이에서는 카드 간격·글자·안쪽 여백을 줄이며 내용이 더 크면 스크롤을 허용한다. 추정 칼로리 안내는 문장별 줄바꿈으로 바꿨다. iPhone 토스 실기기에서 다양한 화면 높이의 한 화면 표시 여부는 재확인 전이다.
- 완료 화면에서 칼로리 추정값이 없을 때 원인을 표시하도록 변경했다. 운동 종류 미선택, 몸무게 미입력, 20~300kg 범위 오류를 각각 구분하고 여러 원인이 있으면 함께 안내한다. 입력값이 유효하면 기존 추정 칼로리 카드가 표시된다. 토스 실기기에서 안내 문구와 한 화면 배치는 새 빌드로 확인해야 한다.
- 사용자 제공 Chrome 로컬 개발 화면에서 완료 결과 카드와 버튼 사이가 크게 비는 것을 확인했다. 원인은 개발 서버가 아니라 완료 버튼 묶음의 `margin-top: auto`였으며, 버튼을 결과 카드 바로 아래로 붙였다. 오른쪽 `AIT` 표시만 개발 도구 UI다. 칼로리 카드는 운동 종류와 유효한 몸무게가 모두 저장되었을 때만 표시된다. 수정 후 토스 실기기 배치는 재확인 전이다.
- 칼로리 추정의 운동 종류에 `실외 자전거`를 추가했다. 기존 `실내 자전거`와 별도 저장값을 사용하며, 2024 Adult Compendium [자전거 활동표](https://pacompendium.com/bicycling/)의 4.3/7.0/9.0 MET를 회복/일반/빠른 구간 가정에 적용했다(2026-11-04 확인). 실제 주행 강도 측정값은 아니다. 토스 실기기 선택창과 완료 화면은 새 빌드로 재확인해야 한다.
- 사용자 제공 수정 후 iPhone 화면에서 완료 요약과 버튼이 세로 중앙에 떠 위아래가 크게 비는 것을 확인했다. 완료 요약을 본문 상단에 붙이고 버튼을 남는 공간의 아래쪽에 배치했다. 짧은 화면에서는 내용 순서대로 스크롤되며 새 토스 실기기 빌드로 재확인이 필요하다.
- 앱별 `AGENTS.md`를 앱 정보·운동 데이터·광고·개발 검사·업로드의 `Key | Value` 표로 정리했다. 토스 콘솔 CLI 업로드 명령(`npx ait deploy`), 최초 토큰 등록, 실행 폴더, 새 QR/deploymentId 확인 절차를 보존했다. 문서만 변경했고 업로드·검수 요청은 실행하지 않았다.
- 사용자 제공 iPhone 토스 실기기 화면에서 완료 화면의 여러 큰 카드 때문에 다시 시작·설정 버튼이 스크롤 아래로 밀리는 문제를 확인했다. 완료 표시를 제목 옆으로 줄이고, 운동 시간·환경·인터벌/BPM을 한 카드로, 추정 칼로리와 근거 안내를 한 카드로 묶어 한 화면에 들어가도록 세로 높이를 줄였다. 짧은 화면에서는 내용 접근을 위해 스크롤을 유지하며, 수정 후 토스 실기기에서 한 화면 표시 여부는 재확인 전이다.
- 홈에 선택형 운동 종류와 몸무게(20~300kg) 입력을 추가하고 로컬 설정에 저장한다. 두 값이 유효할 때 완료 화면에 MET 기반 추정 칼로리를 표시한다. 일반 운동은 선택 운동의 중간 활동 MET, 인터벌은 빠른·회복 구간의 가정 MET를 각각 시간에 곱해 합산한다. 설정 BPM·GPS 속도는 계산에 쓰지 않는다. 최초 구현 시 타입 검사·단위 검사 7개·Vite 빌드 통과. 실제 운동 여부나 강도를 확인하지 못하므로 수치는 측정값이 아니다. 토스 실기기에서 입력 저장·숫자 키보드·완료 화면 배치는 미검증이다.
- MET 근거(2026-11-04 확인): [2024 Adult Compendium 걷기](https://pacompendium.com/walking/) 3.0/3.8/4.8(조깅 회복 구간의 걷기에도 3.8 사용), [달리기](https://pacompendium.com/running/) 7.5/8.5, [자전거](https://pacompendium.com/bicycling/) 4.0/6.8/9.0, [맨몸 운동](https://pacompendium.com/conditioning-exercise/) 2.8/3.8/7.5 MET를 회복/일반/빠른 가정에 사용한다. MET는 성인 집단 기준 활동값이며 개인의 실제 에너지 소비량을 보장하지 않는다. 공식 자료의 출처와 값만 코드에 기록하고 원문 콘텐츠는 배포물에 복제하지 않는다.
- 완료 화면을 완료 표시·운동 시간 강조 카드·환경/템포 또는 인터벌 요약 카드·다시 시작/설정 버튼으로 재구성했다. 좁은 화면에서는 카드가 화면 폭을 넘지 않도록 최대 폭과 줄바꿈을 적용하고, 짧은 화면은 본문 스크롤을 허용한다. 사용자 화면은 입력 초점 확대가 남아 있던 이전 빌드에서 촬영되어 수정 후 완료 화면의 실기기 배치는 재확인 전이다.
- 사용자 제공 iPhone 토스 화면에서 인터벌 사용자 설정의 숫자 입력 시 화면이 확대되어 오른쪽이 잘리는 현상을 확인했다. 숫자 입력칸이 라벨의 약 12.5px 글자 크기를 상속하는 것을 확인하고, 인터벌 및 세부 설정 입력칸·선택창을 16px로 고정했다. 수정 후 iPhone 토스 WebView에서 입력·키보드 닫기·화면 복원은 재검증이 필요하다.
- 사용자가 제공한 토스 실기기 화면에서 운동 정보가 상단에 몰리고 버튼이 하단에 떨어진 배치를 확인했다. 운동 정보와 버튼 묶음의 남는 세로 공간을 위아래에 배분하고, 이어하기·일시정지·초기화를 같은 폭의 세로 목록으로 중앙 정렬했다. 앱 타입 검사·단위 검사 5개·Vite 빌드가 통과했다. 세로 버튼 배치로 바꾼 뒤 토스 실기기 화면은 재확인 전이다.

- 사용자가 제공한 운영 전면형 광고그룹 ID를 토스 앱에 연결했다. 운동 화면 진입 후 미리 로드하고, `loaded`가 확인된 세션이 목표 시간에 도달했을 때만 한 번 표시를 시도한다. 기본·테스트·운영 빌드 모드를 나눠 기본은 광고 없음, 테스트는 공식 테스트 ID, 운영은 발급 ID를 사용한다. [토스 전면형 광고 API](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/interstitial-rewarded-ad.md)와 [운영 정책](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-ad.md)을 2026-11-03 확인했다. 실제 광고 로드·노출은 QR 실기기에서 미검증이다.
- `build:ait:metronome:test`와 `build:ait:metronome:live`가 각각 통과했다. 테스트 JS에는 테스트 ID만, 운영 JS와 `.ait` 압축 내용에는 운영 ID만 있고 테스트 ID는 없었다. 마지막으로 생성된 `moduibeat.ait`는 운영 번들이며 광고 실기기 테스트에는 사용하지 않는다. 앱 단위 테스트 5개와 `git diff --check`도 통과했다. QR 기기에서 로드·표시·닫기·실패 흐름은 아직 확인하지 않았다.
- 세부 설정의 직접 입력·선택 줄을 같은 두 열로 정렬하고 BPM·분 단위를 입력칸 바로 옆에 묶었다. 박자·소리·체크 항목의 도움말 `?`는 제목 바로 옆에 맞췄다. Devtools의 좁은 화면에서 줄 정렬은 재확인해야 한다.
- 인터벌 세부 항목의 허용 범위를 PWA처럼 각 제목 바로 옆에 표시하고 하늘색으로 구분했다. 작은 화면에서는 제목과 범위가 필요할 때 자연스럽게 줄바꿈된다.
- `?`가 설정 제목 오른쪽 끝으로 밀리고 설명이 화면 하단에 고정되던 방식을 PWA와 같은 인접 도움말 방식으로 변경했다. 버튼 위치·팝업 크기를 기준으로 화면 안쪽에 띄우고, 스크롤·화면 크기 변경 시 닫는다. Devtools 실화면에서 팝업 위치는 아직 재확인하지 않았다.
- 토스 Devtools 화면에서 제목·BPM 수치·설정 제목이 어둡게 표시되는 문제를 확인했다. TDS 전역 글자색에 기대지 않도록 앱 컨테이너와 주요 제목·라벨·수치의 밝은 글자색을 명시했다. Devtools 재확인은 아직 필요하다.
- 빠져 있던 토스 앱 도움말을 홈의 환경·템포·시간·인터벌·박자·소리·진동과 운동 화면의 날씨·이어하기·일시정지·초기화에 추가했다. 설명은 화면 안에 고정된 패널에 표시하고 바깥 누르기·닫기·Escape로 해제한다. 실제 토스 Devtools·실기기에서 패널 위치와 터치 동작은 아직 확인하지 않았다.
- 토스 앱의 홈·운동·완료 화면을 PWA의 어두운 배경, 카드·버튼, 하늘색 강조로 맞췄다. TDS 브랜드 색과 Toss 설정의 `primaryColor`도 `#B7F1FF`로 바꿨다. 앱 타입 검사·Vite 빌드가 통과했다. Devtools·토스 실기기에서 최종 색 대비와 버튼 상태는 아직 시각 확인하지 않았다.
- 독립 React/Vite 패키지 `@mini-apps/workout-metronome-toss`를 추가했다. 앱 ID `moduibeat`, 토스 SDK/Devtools 3.9.0, TDS 2.5.1, React 18.3.1을 사용한다. 공식 SDK 안내와 설치 타입에서 설정·위치 구독 API를 확인했다.
- 홈 설정→운동→완료 흐름, BPM·시간·인터벌 프리셋/사용자 설정, 로컬 저장, Web Audio 합성 비트·호르라기, 실외 SDK 위치 구독·좌표 기반 참고 속도, 선택형 MET Norway 예보를 독립 구현했다. 계정·서버는 추가하지 않았다.
- 위치·날씨·토스 WebView 오디오, 화면 잠금·앱 전환, 뒤로가기·안전영역·짧은 화면, CORS, 저장 유지, 실제 광고는 토스 실기기에서 검증하지 않았다. Devtools 화면의 시각적 확인도 남아 있다.
- 로컬 타입 검사·단위 검사 5개·Vite 빌드·`ait build`가 통과해 `moduibeat.ait`가 생성됐다. 개발 서버가 `http://127.0.0.1:5182/`에서 HTTP 200을 반환했다. TDS/SDK 포함 JS는 1,254.21 kB로 Vite 크기 경고가 있다. 번들에서 테스트 광고 문자열은 발견되지 않았다. 이 결과는 토스 업로드·실기기·출시 성공을 의미하지 않는다.
- 잠금 파일 변경 영향 검사: 루트 `pnpm.cmd typecheck`, `test`, `build`가 네 앱에서 모두 통과했다. 기존 세 PWA의 서비스 워커도 생성됐다. 이 검사는 Cloudflare 배포 성공이나 토스 실기기 동작을 의미하지 않는다.
- 외부 콘텐츠: 비트·호르라기·추는 코드와 CSS로 직접 생성했다. 날씨 데이터는 [MET Norway Locationforecast](https://api.met.no/weatherapi/locationforecast/2.0/documentation)에서 조회하며 [이용 조건](https://api.met.no/doc/TermsOfService)·[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)을 2026-11-03 확인했다. 데이터 직접 조회의 CORS·요청 정책은 실제 토스 Origin에서 검증해야 한다. SDK·Devtools는 설치 패키지의 Apache-2.0, React·Emotion·Vite·Vitest는 MIT, TypeScript는 Apache-2.0을 확인했다. TDS 패키지에는 license 필드가 없으며 [앱인토스 제공 범위의 사용 조건](https://developers-apps-in-toss.toss.im/design/components.md)에 따라 사용한다(2026-11-03 확인).

- 전면형 광고는 공식 테스트 ID를 사용한 토스 QR 기기 검증, 운영 번들의 테스트 ID 잔존 검사, 정상 완료·초기화·로드 실패 경로 확인이 남아 있다. 운영 ID로 광고 테스트를 하지 않는다.
- `moduibeat.ait`의 콘솔 업로드·검수·출시는 사용자 명시 승인 후 별도로 진행한다.
